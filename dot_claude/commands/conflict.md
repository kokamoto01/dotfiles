# Git コンフリクト解消

以下の手順でGitのマージコンフリクトを解消してください。

## 1. コンフリクト状態の判定

まずローカルにコンフリクトが存在するか確認する。

- `git diff --name-only --diff-filter=U` でコンフリクト中のファイルがあるか確認する

### ローカルにコンフリクトがある場合 → 手順3へ進む

### ローカルにコンフリクトがない場合 → 手順2へ進む

## 2. リモートのコンフリクト確認

ローカルにコンフリクトがない場合、リモート（PR）側でコンフリクトが発生している可能性を確認する。

1. `gh pr view --json mergeable,mergeStateStatus,baseRefName` でPRのマージ可否を確認する
2. マージ不可（CONFLICTING）の場合:
   - `git fetch origin` でリモートの最新状態を取得する
   - `git merge origin/<ベースブランチ>` でベースブランチの変更をローカルに取り込み、コンフリクトを発生させる
   - 手順3へ進む
3. マージ可能な場合はコンフリクトなしとして終了する

## 3. コンフリクトの解消

1. コンフリクトが発生しているファイルの一覧を確認する
2. 各コンフリクトファイルの内容を読み取り、`<<<<<<<`, `=======`, `>>>>>>>` マーカーを確認する
3. コンフリクトの各セクションについて:
   - 両方の変更の意図を分析する
   - コードの文脈（前後の行、関数の目的、プロジェクト全体の方針）を考慮する
   - 両方の変更を適切にマージする。単純にどちらかを選ぶのではなく、両方の意図を活かした統合を目指す
4. コンフリクトマーカーをすべて除去し、解消後のコードを書き込む
5. 解消後、`git diff` で変更内容を確認する
6. 各ファイルについて、どのように解消したかの要約を報告する

## 注意事項

- コンフリクトが複雑で自動解消が難しい場合は、無理に解消せず、判断が必要な箇所をユーザーに報告する
- `package-lock.json` や `yarn.lock` などのロックファイルのコンフリクトは、手動編集せず `npm install` や `yarn install` で再生成するよう提案する
- テストコードのコンフリクトは、両方のテストケースを保持する方向で解消する

## 4. 解消後の整合性チェック

コンフリクト解消で片方の変更を採用した場合、削除されたコード（import文、変数宣言、関数定義など）がファイル内の他の箇所でまだ参照されていないかを必ず確認する。

1. コンフリクト解消で **削除した側** に含まれていたシンボル（import名、変数名、関数名など）をリストアップする
2. それらのシンボルがファイル内の **コンフリクト外の箇所** で使用されていないか検索する
3. 使用されている場合:
   - 削除したimport/定義を復元する（両方の変更を統合する）
   - または、使用箇所を採用した側の実装に置き換える
4. コンフリクトが発生したファイルだけでなく、同じマージで自動マージされた他のファイルについても、削除されたシンボルへの依存がないか確認する

## 5. コミットとPush

1. 解消したファイルを `git add` でステージングする
2. `git commit` でマージコミットを作成する（コミットメッセージはGitが自動生成するデフォルトを使用）
3. `git push origin HEAD` でリモートにPushする
4. PRがある場合は `gh pr view --json url` でURLを表示する
