# pr

プルリクエストの作成を行います。以下の手順を順番に実行してください。

## オプション

引数: `$ARGUMENTS`

| オプション | 説明 | 例 |
| --- | --- | --- |
| `-b <ブランチ名>` | ベースブランチを指定 | `-b develop` |
| `--switch` | 現在のブランチの変更内容を新しいブランチに移してからPRを作成（ブランチ名は変更内容から自動生成） | `--switch` |
| `--draft` | draft PRとして作成 | `--draft` |

## 1. PR作成先ブランチの準備

以下のいずれかの条件に該当する場合、変更内容から適切なブランチ名を自動生成し、新しいブランチを作成する:
- 現在のブランチが `develop` の場合
- `--switch` が指定されている場合

ブランチ名のフォーマット: `<type>/<短い説明（英語・ケバブケース）>` （例: `fix/clickhouse-timeout`, `feat/add-user-api`）
- type は Conventional Commits の type に合わせる

上記に該当しない場合、現在のブランチをそのまま使用する

## 2. 現状の確認

- `git status` で作業ディレクトリの状態を確認する
- `git diff` および `git diff --cached` で変更内容を確認する
- 未コミットの変更がなければ手順3はスキップして手順4へ進む

## 3. コミット

### 変更のステージングとコミット

- 変更内容を意味のある単位でステージングする
- コミットメッセージは **Conventional Commits** に従うこと

#### Conventional Commits フォーマット

```
<type>(<scope>): <description>
```

| type     | 用途                                     |
| -------- | ---------------------------------------- |
| feat     | 新機能                                   |
| fix      | バグ修正                                 |
| docs     | ドキュメントのみの変更                   |
| style    | コードの意味に影響しないフォーマット変更 |
| refactor | バグ修正でも機能追加でもないコード変更   |
| perf     | パフォーマンス改善                       |
| test     | テストの追加・修正                       |
| chore    | ビルドプロセスや補助ツールの変更         |
| ci       | CI設定の変更                             |

- 変更が多岐にわたる場合は、論理的なまとまりごとに複数コミットに分割する
- **破壊的変更**がある場合は `feat!:` のように `!` を付与するか、フッターに `BREAKING CHANGE:` を記載する

## 4. 既存PRの確認

`gh pr view --json url,title,state,baseRefName` で現在のブランチに紐づくPRが既に存在するか確認する。

### PRが既に存在する場合 → 手順5へ進む

### PRが存在しない場合 → 手順6へスキップする

## 5. 既存PRの更新

既にPRが存在する場合は、新規作成ではなく既存PRを更新する。
ベースブランチは既存PRの `baseRefName` をそのまま使用する（引数やルールによる再判定は行わない）。

1. `git fetch origin` でリモートの最新状態を取得する
2. `git pull --rebase origin <現在のブランチ>` でリモートの変更をローカルに取り込む
   - コンフリクトが発生した場合はユーザーに通知し、解消を案内する
3. `git push origin HEAD` でPushする
4. 既存PRのURLを表示して完了する

※ 手順6以降は実行しない

## 6. ベースブランチの決定

- `-b <ブランチ名>` が指定されている場合、その値をベースブランチとして使用する
- `-b` が未指定の場合、以下のルールで決定する:

| 現在のブランチ名 | ベースブランチ |
| ---------------- | -------------- |
| `hotfix/*`       | `main`         |
| 上記以外         | `develop`      |

- `develop` → `main` のマージはGitHub上で直接行うため、このコマンドでは扱わない
- 現在のブランチが `main` または `develop` の場合はエラーとして中断し、作業ブランチを作成するよう案内する
- 判定結果をユーザーに提示し、変更の希望があれば従う

## 7. リモートへのPush

- `git push origin HEAD` で現在のブランチをリモートにPushする
- Push先のリモートブランチが存在しない場合は `git push -u origin HEAD` を使用する

## 8. PRテンプレートの確認

- リポジトリ内の `.github/PULL_REQUEST_TEMPLATE.md` を読み込む
- テンプレートが存在しない場合は、手順9のデフォルト構成で本文を作成する

## 9. PR本文の作成

`git log --oneline <ベースブランチ>..HEAD` とdiffの内容をもとに、PRの説明文を作成する。
コードの差分から「何を変えたか」だけでなく、「なぜこの変更が必要か」を考察し、背景・動機を説明文に含めること。

### テンプレートがある場合

- テンプレートの構成に従って各セクションを埋める
- 変更概要のセクションには、diffから読み取れる内容を要約して記載する
- 背景・動機に該当するセクションがあればそこに、なければ概要に「なぜこの変更が必要か」を含める

### テンプレートがない場合

以下の構成で本文を作成する:

```markdown
## 概要

## 変更内容

## 関連Issue
```

## 10. PRの作成

以下のコマンドでPRを作成する:

```bash
gh pr create --base "" --title "" --body ""
```

- PRタイトルは、変更全体を表すConventional Commits形式の要約とする
- 引数に `--draft` が指定されている場合のみ `--draft` フラグを付与する。指定がなければ確認せず通常PRとして作成する
- 作成後、PRのURLを表示する
